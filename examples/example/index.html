01 / QUICK START

A small addition to your stack.

Install the ESM package with paired TypeScript declarations. These examples target SDK 0.3.0; use @0.3.0 for a reproducible pin.

Terminal
npm install @youge/assistant-sdk

Use a modern ESM-aware browser bundler, or Node.js 18+ for server-side use. React is an optional peer, not a core dependency. Browser installation and worker features require a secure context (HTTPS, or localhost for development).

Create an isolated instance for your own UI. Import and call this setup once at your app’s client entry point; call the returned cleanup when it unmounts.

TypeScript / JavaScript · @youge/assistant-sdk
import { YouGeAssistant } from '@youge/assistant-sdk';

function basicIntegration() {
  const assistant = YouGeAssistant.create({
    project: { id: "my-web-app" },
    theme: "auto",
    position: "bottom-right",
    branding: { name: "My web app", themeColor: "#6942d6" },
    modules: {
      installation: true,
      diagnostics: true,
      updates: true,
      autoUpdate: false,
      userUpdate: true,
    },
  });

  const unsubscribe = assistant.subscribe((state) => {
    console.log("Assistant notices:", state.badge.count);
  });

  // Call when this isolated integration unmounts.
  return () => {
    unsubscribe();
    assistant.destroy();
  };
}

Core initialization does not install a worker, display a widget, or fetch your endpoints. To share state with classic scripts and the optional widget, use YouGeAssistant.attach() instead of create().

02 / CONFIGURATION

Enable only what you need.

Modules include installation detection and guidance, update detection and notifications, automatic or user-controlled updates, offline and cache diagnostics, recovery, failover, help, and Chrome handoff. Browser support and connected toolkit/adapters determine which actions are available.

configure() updates the existing instance synchronously. Nested overrides such as modules are replaced, not deep-merged: preserve the resolved settings when changing individual flags.

TypeScript / JavaScript · @youge/assistant-sdk
import { YouGeAssistant } from '@youge/assistant-sdk';

function updateConfiguration() {
  // Use attach() when sharing state with the classic toolkit/widget.
  const assistant = YouGeAssistant.attach();
  assistant.configure({
    theme: "dark",
    modules: {
      ...assistant.getConfig().modules,
      updateNotifications: false,
      cacheDiagnostics: false,
    },
  });
}

Runtime overrides are not persisted or synchronized. Save authoritative settings through your host’s authenticated backend, validate an allowlist, and apply them on startup. If loading classic pwa.js, set the same initial policy in window.YOU_GE_ASSISTANT_CONFIG before that script can act.

Disabling a capability gates future Assistant-managed actions; it cannot undo an activation or other work already started.

03 / EXISTING APPLICATIONS

Keep your logic. Connect the signals.

Call these setters from your existing health and session handlers using their real results. The values below illustrate a healthy response, not an SDK health check. Subscriptions let any UI framework render the same state.

TypeScript / JavaScript · @youge/assistant-sdk
import { YouGeAssistant } from '@youge/assistant-sdk';

function existingApplication() {
  const assistant = YouGeAssistant.attach();
  // Feed results from YOUR host's health/auth logic; the SDK doesn't fetch them.
  assistant.setEndpointStatus({ primary: "healthy", backup: "inactive" });
  assistant.setSessionStatus({ state: "ok" });
  const unsubscribe = assistant.subscribe((state) => {
    document
      .querySelector("[data-assistant-status]")
      ?.setAttribute("aria-label", state.badge.label);
  });
  return unsubscribe; // Remove this view's subscription on unmount.
}

React 18+ can use createUseAssistant from @youge/assistant-sdk/react with the host’s useSyncExternalStore. Keep the instance getter stable; do not call attach({ …options }) on every render. Domain matching selects public branding, never authorization.

04 / HOST-OWNED WORKERS

Your worker remains yours.

Already have a worker?

Keep its script, scope, registration, caches, handlers and framework update flow. Use an explicit host-owned adapter via the existing runtime bridge. Do not point Assistant worker messages at a custom worker.

No worker yet?

The host may independently choose the optional repository you-ge-sw.js. Copy the toolkit’s runtime and precache assets together; serve over HTTPS and register it explicitly in host code.

The following is an optional new-host setup only for an app without an existing worker, hosted at /portal/. It is not required for the SDK. Adjust the path to your deployment; never run both a framework registration and this registration.

Host entry point · not an SDK API 
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/portal/you-ge-sw.js', {
    scope: '/portal/',
  });
}

Separately, the host must opt the classic PWA runtime into that exact Assistant worker. No opt-in means no Assistant worker messaging or lifecycle management.

Host HTML · optional toolkit assets 
<script src="/portal/pwa.js" defer
  data-assistant-worker
  data-sw="/portal/you-ge-sw.js"
  data-sw-scope="/portal/"></script>

These assets come from this repository’s toolkit build, not from an npm SDK widget export. Follow the complete asset and hosting checklist before deploying. Cache diagnostics may return unavailable without a compatible opted-in worker or adapter.

Migrating from automatic worker registration

Move registration into host-owned code only if you deliberately selected the optional Assistant worker. Set explicit opt-in on pwa.js. If you have a custom/framework worker, retain it and integrate through its own adapter. Do not unregister workers or clear caches as part of migration. Legacy compatibility shims remain migration-only.

05 / SAFE TEARDOWN

Easy to add. Safe to switch off.

TypeScript / JavaScript · @youge/assistant-sdk
import { YouGeAssistant } from '@youge/assistant-sdk';

function disableAssistant() {
  const assistant = YouGeAssistant.attach();
  assistant.configure({ enabled: false });
  // Host worker, caches and host update lifecycle are unchanged.
  // Re-enable with assistant.configure({ enabled: true }).
  // Only the application owner should destroy a shared singleton at teardown.
}

Remove view subscriptions when they unmount. Use destroy() for an isolated instance or application-owned shared teardown to remove Assistant listeners. Neither operation unregisters the host’s worker, deletes its caches, or disables its offline handling.
